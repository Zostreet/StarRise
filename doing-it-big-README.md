# Doing It Big

A public recognition board for overlooked artists and creators, including people without StarRise membership. Home, Community, Creator Studio and Admin Center link to it. No fictional creators or endorsements are prepopulated.

Published spotlights credit and link to the original creator's HTTPS work. Visitors can browse/search/filter the most recent 100 matching spotlights. Registered members can nominate themselves or another creator and see their own review status. Nominations remain private to the submitting account and existing administrators. A nominee never needs a platform account. The database enforces five nominations per 24 hours with an advisory lock. Anonymous-auth accounts cannot submit. Members cannot spoof a nominator or directly change review state.

Existing `platform_admins` accounts get the review queue, can write a public summary, publish/update, decline or hide recognition. No new administrator is assigned. Published recognition is readable publicly; hidden recognition is available only to administrators. Hiding and republishing are reversible. No automatic invitations, email, social messages or external media mirroring are sent. Removal/correction requests use existing Support. Public content is limited to name, field, city/scene, original work link and reviewed summary; nominator identity is never copied into the public table. Browser UI uses textContent and HTTPS link validation, with local pinned Supabase 2.117.3, CSP and no secret/service key.

Migration `20261011144408_doing_it_big_spotlight.sql` matches the applied migration history. RLS and restricted grants cover both tables. Only authenticated users can invoke the review RPC, which independently checks a permanent account and the existing administrator registry with an empty search_path. Its authenticated SECURITY DEFINER advisor warning is intentional for this guarded publication operation; there is no anonymous execution grant. The public feed's anonymous visibility is intentional. The private-schema submission trigger rejects anonymous users and serializes daily-limit checks.

`scripts/spotlight-access-test.sql` verifies own/stranger/admin/anonymous read/write, unauthorized publishing and status changes, identity spoofing, admin publication, reversible hiding, public feed access, and daily limits. All synthetic accounts, profiles, subscriptions, nominations and spotlights roll back; zero sample spotlights are left public. Real signed-in UI submission/review requires the user's account and is not claimed by these database checks.
